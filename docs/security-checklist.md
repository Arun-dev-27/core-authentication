# Security checklist

Status legend: ✅ implemented and covered by automated tests · 🟢 implemented · 🔶 deployment/operational responsibility

## Origins, framing and callbacks
- ✅ Exact origin matching only (no wildcard/prefix/suffix/regex) — `origin.util.spec`, `client-policy.spec`, e2e look-alike origin test
- ✅ Wildcards rejected when registering origins/URIs; DB `CHECK (origin !~ '\*')` — `uri-policy.spec`, authz e2e
- ✅ Dynamic CSP `frame-ancestors <exact origin of this transaction>`; error pages `frame-ancestors 'none'` — e2e
- ✅ Browser can only *select* a registered callback; arbitrary callbacks rejected — e2e
- ✅ postMessage target origin is the exact registered origin, never `"*"` — `public/login.js`, e2e asserts `target_origin`
- ✅ Login page has no inbound `message` listener; DOM built with `textContent`
- 🟢 Fetch-metadata (`Sec-Fetch-Dest`) and Referer checks when present
- 🟢 BU reference frontend validates `event.origin`, `event.source`, type, transaction, state, exact key set

## CSRF, sessions, cookies
- ✅ Per-transaction CSRF token (`x-csrf-token`) + Origin must equal the issuer for state-changing calls — e2e
- ✅ Portal CSRF token bound to the signed-in session (`sid`) after login: valid for the session lifetime, refused for any other session — e2e
- 🟢 `POST /auth/transaction` returns the transaction's CSRF token only when `TRANSACTION_API_RETURNS_CSRF` is true (default off in production); the Origin check still applies — unit, live
- ✅ Client configuration is read fresh for transaction creation, the login page and sign-in: a removed origin or suspended client is refused on the very next request, without a refresh call — unit, e2e, live
- ✅ BU reference session cookie: JWE (`dir`, `A256GCM`) with the application's own key, bound to its origin and client_id, revoked through the Redis session on local or back-channel logout — unit
- ✅ Cookie holds only an opaque 256-bit handle; Redis indexes its SHA-256; `sid` in assertions is a different value — e2e
- ✅ `HttpOnly; Secure; SameSite=None; Path=/` — e2e; production config refuses `COOKIE_SECURE=false`
- ✅ New handle on every password login (session fixation); user switch logs the previous user out everywhere
- 🟢 Idle (sliding) + absolute session lifetime
- ✅ Session revocation (browser, service-initiated, disabled user on SSO continue) — e2e
- 🟢 Third-party-cookie fallback: top-level `display=page` + form_post with CSP `form-action` limited to the callback origin

## Credentials and brute force
- ✅ scrypt (N=2^15, r=8, p=1), random salt, constant-time compare, rehash on parameter upgrade — `password-hasher.spec`
- ✅ Uniform `INVALID_CREDENTIALS` for unknown user / wrong password, dummy-hash timing equalisation — e2e
- ✅ Account status revealed only after a correct password — e2e
- ✅ Redis rate limits per IP and per identifier + durable DB lockout, `Retry-After` — e2e
- ✅ Passwords only in the Authentication DB; Authorization DB has no password columns and rejects credential fields — authz e2e
- 🟢 Legacy migration: decrypted plaintext exists only in memory, immediately re-hashed; nothing logged
- 🔶 MFA: schema (`auth_mfa_factors`, `mfa_enabled`) is present; challenge flow not yet implemented

## Assertions and keys
- ✅ RS256 only, `kid` header, complete compact JWS returned — e2e
- ✅ Claims limited to `iss sub aud sid jti txn auth_time iat exp`; no roles/permissions/tokens/passwords — e2e asserts exact claim set
- ✅ 60 s lifetime, single-use transaction (atomic), `jti` replay protection at the BU — e2e + `bu-verifier.security.spec`
- ✅ Verifier rejects alg=none, HS256 key confusion, unknown/missing kid, wrong key, tampered payload, wrong iss, aud mismatch
  (including array audiences), expired, future `iat`, long lifetime, wrong txn, typ confusion — `bu-verifier.security.spec`
- ✅ Key rotation NEXT→ACTIVE→RETIRING→RETIRED; old assertions verify during RETIRING — `keyset.spec`, e2e
- ✅ JWKS exports only `kty n e kid alg use` — `keyset.spec`, e2e
- ✅ RSA ≥ 2048 bits enforced (3072 generated by default)
- ✅ Private keys only in AWS Secrets Manager (KMS CMK, new version per rotation) or SSM; public keys only via JWKS; production refuses the file provider — `secrets-manager-keys.e2e-spec` (LocalStack)
- 🔶 IRSA grants GetSecretValue to Identity pods only; secret resource policy denies all other principals
- 🟢 JWKS `Cache-Control: max-age=300`; BU verifier caches 10 min with 30 s refetch cooldown

## Authorization
- ✅ Deny-by-default engine: client ACTIVE → app/BU/utility ACTIVE → user ACTIVE → app access → role → permission — authz e2e
- ✅ Permissions of one application can never satisfy another — authz e2e
- ✅ No API keys anywhere: service principals authenticate with single-use RS256 service tokens verified against their own JWKS; administrators with Identity access tokens (`at+jwt`) whose rights come from Core RBAC — authz e2e, `token-verifier.service.spec`, identity e2e
- ✅ Token-kind separation by `typ` + `aud` (login assertion, logout token, service token, access token cannot be swapped) — `token-verifier.service.spec`, `bu-verifier.security.spec`
- ✅ BU service principals scoped to `AUTHZ_CHECK` and their own client IDs; user tokens rejected on service-only routes; revoked principals rejected — authz e2e
- ✅ Cache invalidated on every model change (versioned keys) — revocation/suspension e2e
- ✅ Client lifecycle cannot skip SECURITY_REVIEW; ACTIVE requires origins + callbacks — `client-lifecycle.spec`, authz e2e
- 🟢 BU backends fail closed when the Authorization service is unreachable

## Logging and audit
- ✅ Redaction of password, assertion, logout token, access tokens, Authorization headers, cookies, private keys — `logging-redaction.spec`
- 🟢 Query strings stripped from request logs (state/txn); request bodies never logged
- 🟢 Correlation ID (`x-request-id`) propagated Identity → Authorization, stamped on logs and audit rows
- 🟢 Authentication audit: render, reject, login success/failure, assertion issued (jti only), session end, federation + back-channel logout, legacy migration
- 🟢 Authorization audit: every admin change, every DENY (ALLOW optional)

## Platform
- 🟢 Helmet: HSTS (prod), nosniff, CORP same-origin, no-referrer; default CSP `default-src 'none'; frame-ancestors 'none'` + `X-Frame-Options: DENY` on non-embed routes
- 🟢 Strict DTO validation (`whitelist`, `forbidNonWhitelisted`), 64 KB body limit (Identity)
- 🟢 Health `/health`, readiness `/health/ready` (DB, Redis, keys)
- 🔶 TLS termination at ALB with TLS 1.2+ policy, AWS WAF rate rules, private subnets for RDS/ElastiCache, VPC endpoints for Secrets Manager/KMS
- 🔶 Swagger disabled in production (`SWAGGER_ENABLED=false`)
- 🔶 BU service-principal key rotation: publish the new key in the backend JWKS before signing with it; revoke principals with `npm run principal:register -- --id <id> --revoke`; restrict NetworkPolicy egress
